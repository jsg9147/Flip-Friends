# Quantum 경사 이동 — 제품8

- 상태: Historical (제품8 구현·검증 기록). Unity6000.6.8f1·Quantum3.0.14 Stable2241은 유지했다.
- 합의는 제품8/ff-product-8이다. 기존 콘텐츠2:2~6:6·공식1의 해시는 보존하고 제품 규칙 서명에 플레이어30도·상자45도·급경사 미끄럼/법선 점프를 넣었다.

## 원본 기준과 지원 범위

- `Controller2D.maxSlopeAngle` 클래스 기본은45도지만 실제 `Assets/03_Prefabs/Player.prefab`은30도다. `Box.prefab`의 `PickupObj.maxSlopeAngle`은45도다. 코드 기본값만 보고45도로 이식하지 않는다.
- `ClimbSlope`는 수평 이동 거리의 cos를 X, sin을 Y로 바꾼다. `DescendSlope`도 접선 거리로 이동하고 기존 하강량을 더한다. 걷기4·달리기5.5·가속/반전·점프13.2·가변 점프·달리기 보너스는 기존 Quantum 값을 유지했다.
- 지원 경사는 정지 시 미끄러지지 않고 접지 수직 속도0이다. 일반 점프는 수직이며 점프 상승량이 경사 상승량보다 크면 붙잡지 않는다. 원본의 비활성 벽 점프나 일반 BlockJump 차단은 켜지 않았다.
- 플레이어의30도 초과~45도 지형은 등반 대상이 아니다. 원본의 급경사 하강·법선 점프와 경사 안쪽 방향 입력일 때의 급경사 점프 거부를 이식했다. 이 제한은 일반 점프 차단과 다르다.
- 상자는45도까지 중력·던지기·수평 감속·경사 착지/이동을 지원한다. 정지 상자의 자동 활주·회전/구르기·밀기 조작을 새로 지원한다고 표시하지 않는다.45도 초과 지형은 작성기에서 거부하므로 원본의45도 초과 상자 활주는 제품 지원 범위가 아니다.

## FP 충돌과 미세 단차

- `FlipFriendsTerrain.Support`가 기존 짝홀 점유 판정을 사용해 윤곽 방향·구멍과 무관하게 위쪽 지지면을 고른다. 천장·섬 밑면은 제외한다. FP 유리수 바깥쪽 반올림은 기존 `Range`와 공유한다.
- `PrepareSlope`는 기존 Quantum AABB 크기·축 충돌 순서를 유지하면서 접선 이동량과 지지면 높이를 계산한다. 평지→오르막에서는 경사 시작까지의 평지 거리를 따로 보존한다. 상승/수평의 지형·상자·플레이어·실제 운반물 크기 검사를 끝낸 뒤에만 위치를 반영한다. 천장/벽에 막히면 FP 이분 탐색으로 이동량을 줄인다.
- 상승/수평 교차의1raw 반올림 차이를 피하려고 상승 시2raw 여유를 둔다. 같은 틱의 아래축 검사로 즉시 지지면에 돌아오며 누적 상승하지 않는다.
- `min(abs(dx),abs(dy)) ≤ 8raw`인 Composite 미세 변은 종전 미세 단차 경로로 남긴다. 본격적인 경사 투영과 구분하며 null/빈 윤곽은 기존 이동 경로다. 기존8raw 한계를 높이지 않았다.
- 작성기는45도 이하 비축정렬 변을 허용한다. 그 밖은 `지형 ID·변번호·양 끝 위치·최대45도 초과`로 전체 거부한다. 수직 벽과8raw 미세 변은 종전처럼 허용한다. MapData 배치 범위(x−50~50 등)는 바꾸지 않았다.

## 별도 공식 시험 콘텐츠

- `Assets/03_Prefabs/OfficialStages/Official Slope Test.prefab`, ID `official-slope-test`, 표시 `경사 시험`이다. 원본 `official-test` 프리팹/콘텐츠는 수정하지 않았다.
- x0~8에서4 높이로 오르는 약26.565도 경사, x8~12 정상 평지, x12~20 내리막, 양쪽 평지·2인 시작·상자·도착으로 구성했다. `QuantumSlopeSetup`이 Unity API로 타일/PNG 임포터 물리 윤곽·프리팹을 저장하고 기존 공식 작성기로 Map/Terrain/Stage/씬·목록을 만든다.
- `Sprite.OverridePhysicsShape`의 런타임 형상은 재로드 뒤 사라져 사각 계단으로 바뀌었다. TextureImporter의 물리 윤곽으로 저장하도록 수정했고, 프리팹 재판독의 실제 경사 변과 해시를 검사한다. 타일/프리팹/씬 YAML과 meta GUID는 수동 작성하지 않았다.
