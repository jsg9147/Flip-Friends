# 제품13 컨베이어 벨트 원본 근거와 검증

- 상태: Historical. 구현 범위와 다음 작업은 [Quantum 전환 문서](../QUANTUM_MIGRATION.md)를 따른다.

## 원본 근거

- `Conveyor`는 방향만 가진다. `OnOffManager.ApplyState`가 `isClockwise = isActivated`로 덮어쓰며 매니저는 서버 시작 때 `false`로 적용한다. 그룹 벨트는 반시계(오른쪽)에서, 그룹 없는 벨트는 기본값 시계(왼쪽)에서 시작한다. 자동 전환은 3초 코루틴이다.
- 적용 대상은 플레이어뿐이다. `Controller2D.VerticalCollisions`가 위·아래 세로 충돌 대상의 `Conveyor`를 `onConveyor`로 기록하고 옆면은 제외한다. 레이 순서상 마지막(오른쪽) 레이의 충돌 대상이 남는다.
- `MovementHandler`: SmoothDamp·중력 뒤 벨트 위면 `ext ∓= 1×dt×1`(Player.prefab `conveyorSpeed1`·`conveyorAccelerationSpeed1`, 시계면 음수)·±1 클램프, 아니면 `Lerp(ext,0, 접지 dt×5 : dt)`. 로프 덮어쓰기 뒤 `velocity += ext`를 **50Hz 틱마다** 더하고 `velocity`에 누적된다. 정지 입력 정상상태는 약 14.5/초, 역방향 걷기에도 약 10.5/초로 밀린다(Python 재현).
- `Launch`(운반 시작·해제/던지기·복귀 Teleport)만 외부 속도를 0으로 만든다. 피격·스프링/바운스는 속도만 덮어써 외부 속도가 남는다. 이동 발판 승객 변위는 `Simulate` 첫머리에서 먼저 적용된다.
- 벨트 Collider는 오프셋(1~3,0)·트리거 Box지만 `queriesHitTriggers`와 Player 마스크(Conveyor 레이어16 포함)로 플레이어에게는 고체다. Box 마스크(3392)에는 16이 없어 상자는 통과한다. 원본21개 스테이지의 벨트 스테이지(18~21)에는 상자가 없다.
- 실제 배치: Stage18 고정5·수동 그룹1, Stage19 고정8·수동 그룹1, Stage20 자동3초+스위치 그룹 두 개(벨트9·1, 지형 없음), Stage21 자동3초+스위치 그룹 두 개(벨트1·3). Stage20 `Conveyor belt (9)`는 `PlatformController` 속도0(정지), Stage21 `Conveyor belt (6)`는 속도4·비왕복·경유점(0,5)/(7,15)·승객 Player 전용 이동 벨트다.

## Quantum 규칙과 원본 차이

- 60Hz는 틱당 가산을 `ext×50×DeltaTime`으로 환산한다. 3초 궤적 오차 1~2%(환산 없이 60Hz 가산하면 정상상태 +19%).
- 벨트 판정은 같은 ID의 고체 Platform(Kind0) 발판이며 고정 벨트는 속도0 발판이다. 상자도 고체로 서지만 외부 속도는 받지 않는다(원본 통과와 의도적 차이: 보이는 고체를 상자가 통과하는 규칙을 새 콘텐츠에 들이지 않는다).
- 접촉은 이동 뒤 접지/천장 윗면·아랫면(16raw 허용, X 겹침)이며 여러 벨트는 가장 오른쪽을 고른다. 벨트와 지면에 걸치면 벨트를 적용한다(원본은 오른쪽 레이 대상에 따라 무적용 가능).
- 운반 시작·던지기/내려놓기·복귀·도착은 외부 속도와 접촉을 0으로, 피격·발사는 유지한다. 운반된 플레이어는 이동을 건너뛰어 벨트가 적용되지 않고 운반자는 적용된다.
- 지형과 같은 이름의 그룹 벨트는 지형의 **적용 상태**를 따른다(점유 대기 중 방향 유지, 해소 틱에 함께 전환). 벨트만 있는 그룹은 첫 벨트가 수동 홀짝을 저장하며 자동 위상과 합산해 같은 틱에 한 번 적용한다.
- 거부: 트리거/오프셋/회전·배율/다중 Collider·전환 지형 혼합·트랩 종류 이동 장치, 그룹 없는 벨트의 간격, 지형 그룹과 다른 간격, 벨트 그룹 간격 불일치, 스위치 없는 벨트 전용 수동 그룹, 문이 벨트 그룹을 대상으로 하거나 문 그룹에 벨트 연결, 스위치의 지형·벨트 동시/무참조.
