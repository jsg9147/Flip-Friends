- 승객 운반은 플레이어 예측과 충돌하므로 별도 변경 단위로 구현한다. 기존 속도·위상·대기를 보존한 시간 기반 발판 이동량을 서버/소유 클라이언트의 Simulate에 같은 규칙으로 적용하는 방안을 우선 검증한다.
- 검증: 시작 지연·왕복·완주·낙하·복귀·이동 중 리셋, 코루틴 잔존 없음, 다중 승객·상자 지원 범위, 지연 조건에서 보정 떨림/관통 여부.
- 완료: 리셋 시 초기 위치와 모든 진행 상태가 복원되고 호스트/원격 클라이언트의 발판 위치·판정·승객 이동이 일치한다.

### 단계 5 — 장애물·발사체·인원별 배치·전체 회귀
- 범위: MovingTrap, RotatingObstacle, CannonShooter, DynamicObj와 로딩/공통 기반의 필요한 보강.
- 복구: 전체 대포의 projectilePrefab·Rigidbody2D·NetworkIdentity·클라이언트 spawn 등록, 회전 장애물의 동기화 대상, Stage 1~6 위치 동기화 참조를 검사한다.
- 검증: 발사 지연·주기·속도·파괴 범위, 서버 전용 발사체 이동, 서버 확정 랜덤 회전, 1~4인 시작 위치, 이동/회전 경로·콜라이더 변경 없음.
- 완료: 21개 스테이지 로드/클리어/정리 및 영향받은 맵 에디터 팔레트 테스트 플레이에서 기존 동작이 유지된다.

### 모든 단계의 검증·마이그레이션 완료 기준
- 프리팹 변경은 Unity 에디터의 SerializedObject/PrefabUtility로 수행하고 재로드한 저장 에셋을 다시 검사한다. YAML 대량 편집·GUID 수동 생성은 하지 않는다.
- 직렬화 필드명/타입은 우선 보존한다. 이름 변경은 FormerlySerializedAs, 타입/소유권 변경은 명시적 에디터 마이그레이션과 변경 전후 값 대조로 처리한다.
- 필수 참조 누락은 오브젝트 경로를 포함해 진단하고 해당 동작을 안전하게 중단한다. 정상 선택 값이나 의도적 고정 방향은 오류로 취급하지 않는다.
- 코드 변경마다 Assembly-CSharp 빌드와 Unity 컴파일/Mirror Weaver를 확인한다. 새 에디터 코드가 있으면 해당 에디터 어셈블리도 검사한다.
- 순수 상태 전이는 작은 독립 어셈블리의 EditMode 테스트로, MonoBehaviour/프리팹 통합은 에디터 검사·PlayMode/MCP 검증으로 확인한다. 기존 테스트 asmdef가 Assembly-CSharp를 직접 참조한다고 가정하지 않는다.
- 네트워크 검증은 호스트+원격 클라이언트 및 LocalNetworkTest 지연 조건을 포함한다. 게임 중 신규 입장 허용 정책은 바꾸지 않고 초기 스폰 시 SyncVar 적용을 검증한다.
- 실제 실행하지 못한 2~4인·Steam·서버 전용 검증은 통과로 표시하지 않는다. 각 단계의 미해결 설계 항목도 완료와 구분한다.
- 각 단계 결과는 해당 기능 문서의 현재 상태·검증·다음 작업에 반영하고 기존 미커밋 변경을 보존한다. 독립 문서가 필요하면 라우터에 등록한다.
