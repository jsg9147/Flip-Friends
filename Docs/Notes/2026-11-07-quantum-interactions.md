# Quantum 제품 밟기·운반·상자 이식

## 환경과 보존

- Unity 6000.6.8f1, `Assets/Photon/Quantum/build_info.txt` = 3.0.14 Stable 2241, CLI beta.17. 버전을 변경하지 않았다.
- 시작 시 Git 미커밋·미추적 파일이 다수 있었으며 모두 보존했다. 실행 중인 Unity 프로세스는 없었다. 프로젝트를 연 직후 Main dirty=false, 첫 Play 종료 후 dirty=true였다. Main을 강제 저장·폐기하지 않았다.
- 새 상호작용 맵은 additive 작성 씬에서 Unity API로 생성·베이크·저장·재로드했다. 원래 열린 Main과 Undo/미저장 상태를 유지했다. 기존 Main/QuantumPlay·프리팹·정적/로프 맵 원본과 베이크는 덮어쓰지 않았다.
- [공식 SDK 설치 표](https://doc.photonengine.com/quantum/v3/getting-started/initial-setup)는 6000.5까지 명시한다(2026-11-07 재조회). 6000.6에서의 아래 프로젝트 실행 결과를 공식 지원 보장으로 해석하지 않는다.

## Mirror 실제 실행 근거

- `MovementHandler.PlayerMovementInteract`는 Controller2D가 이전 이동에서 찾은 머리 접촉을 다음 Simulate에서 소비한다. 튕김은 13.2, 점프 유지 시 ×1.2, X에 상대와의 위치 차이 ×0.5를 더한다. 밟은 쪽 반복 밟기·등반 제한 0.3초, 밟힌 쪽 BlockJump 0.15초다.
- 주의: 이름과 달리 기존 `isJumpBlocked`는 반복 밟기 검사에만 연결되어 있고 일반 지상 점프 입력에는 연결되지 않는다. Quantum에서도 일반 점프 차단을 새로 활성화하지 않았다. 벽 미끄럼·벽 점프도 여전히 비활성이다.
- `Shrink.anim`은 0.5초 동안 판정 (0.8,0.5), 오프셋 (0,-0.25)다. Quantum은 30틱과 해당 판정을 프레임에 저장하고, Unity는 눌린 그림만 표시한다. Animator/Unity 콜라이더로 판정하지 않는다.
- 기존 Quantum의 기본 판정 (0.8,1), 오프셋 0은 이동 회귀 보존을 위해 유지했다. Mirror Player 루트의 기본 판정 (0.9,0.8), 오프셋 (0,-0.1)과 같다고 주장하지 않는다. 두 기본 판정의 발바닥 높이는 같다. Shrink 종료 시 Quantum 기본 판정으로 돌아간다.
- `PlayerInteraction`의 실제 Player 프리팹 값은 heldPos=(0,0.95), 들기→해제 간격0.15초, 탈출 제한1.5초, 탈출 요청 간격0.25초, 플레이어 던지기(7,12), 제한0.4초다. 상자 throwForce는 클래스 기본3이 아닌 프리팹의6이다.
- 탐색은 몸체 양옆에서 0.2 길이 레이10개, 간격 너비/8, 아래에서 한 간격 낮게 시작한다. 머리 위 (0.9,0.9) 영역이 비어 있어야 하며 플레이어를 상자보다 먼저 찾는다. 운반 중인 플레이어·다른 것을 든 플레이어는 들지 않는다.
- 놓기 후보는 앞(발바닥+타깃 반높이+skin0.02) → 머리 위 → 운반자 자리다. CanOccupy는 skin×2 안쪽을 검사한다. 기존 마지막 후보는 무검사였으나 이번에는 마지막 후보도 검사하고 모두 막혔으면 운반 관계를 유지한다. 지형 안에 놓이지 않도록 한 의도적인 차이다.
- 던질 플레이어는 머리 위, 막혔으면 운반자 자리부터 고른다. 상자는 머리 위가 막히면 놓기 후보 순서를 사용한다. 해제 시 양방향 관계·스무딩·등반·접지·속도를 함께 갱신한다.
- 던진 플레이어의 기존 제한은 입력 무시가 아니라 수평 SmoothDamp 시간을1초로 바꾸고 로프 점프를 제한한다. Quantum도 이를24틱 동안 적용한다. 상자는 중력9.8·수평 SmoothDamp1.5초·낙하 제한12를 사용한다. 기존 상자 wallSliding에도 활성 대입 경로가 없어 켜지 않았다.
- Mirror 상자의 Reset/추락/소환 API는 조사했지만 이번 범위에서 이식하지 않았다. Quantum 새 맵은 폐쇄된 정적 공간이며 추락 복귀·리셋·장치는 미지원이다.

## 결정론과 제품 연결

- 모든 관계·속도·스무딩·입력 유지값·방향·타이머·이전 위치·접촉 대상은 qtn 프레임 상태다. 양 축·Jump/Run/Interact가 기록 입력에 포함된다. 고정소수점과 Quantum DeltaTime만 판정에 사용한다.
- 시스템 순서는 상호작용/이전 위치 스냅샷 → 플레이어 이동 → 상자 이동 → 운반 추종 → 전원 완료다. 밟기 속도는 기존처럼 이동의 중력/스무딩 계산 뒤 적용한다. 플레이어 몸체의 옆/위 충돌과 내려가는 머리 접촉을 구분한다. 머리 위에 계속 서는 상태를 추가하지 않았다.
- 같은 틱의 밟기·들기 요청은 전역 PlayerRef 오름차순이다. 플레이어 탐색은 레이 번호→거리→PlayerRef, 상자는 레이 번호→거리→동일 거리에서 정렬된 콘텐츠의 EntityRef 생성 순서다. 자기·중복·연쇄/순환 운반을 차단한다.
- 탈출90틱/요청15틱·해제9틱·던지기 제한24틱을 프레임에 둔다. 들린 동안 이동/점프·들기 입력은 이동 시뮬레이션에 적용하지 않는다. 해제 즉시 운반자와의 충돌 제외가 끝난다.
- 도착 시 들고 있던 대상을 안전하게 놓고 완료한다. 놓을 공간이 없으면 도착을 보류한다. 도착 후 입력을 무시하고 속도·스무딩·등반/접촉·타이머를 정리한다. 세션 종료는 러너 프레임 전체와 표시/입력 구독을 폐기한다.
- Main의 기존 정적/로프 두 맵에 새 `FlipFriendsInteractionMapManifest`를 런타임 등록한다. 새 버튼도 기존 준비 화면/선택 목록에 등록하므로 Main 씬을 덮어쓸 필요가 없다. 첫 제품 경로이며 전체 게임 전환이 아니다.
- 고정 키: 1P A/D·W/S·Space·왼쪽 Shift·E, 2P 방향키·오른쪽 Ctrl·오른쪽 Shift·Enter. 아래+E/Enter는 놓기다. 온라인은 각 연결의 로컬슬롯0을 읽고 자동 시험만 GetLocalPlayers로 전역 PlayerRef를 얻는다. 기존 단일 Player 액션/PlayerPrefs bindings의 재설정과 게임패드·Reset은 미연결이다.
- MapData2.1 유지. 상자 없는 기존 원본은 변환/팔레트2와 기존 해시를 유지하며 상자 포함 콘텐츠는3:3을 요구한다. 상자 중심·크기·물리 규칙도 해시에 포함한다. 새 제품 규칙은 `제품3`, 온라인은 `ff-product-3`이며 v2 콘텐츠도 제품3 동작으로만 합의한다.
- 상자는 `interactive.box`의 원본 루트 박스0.9·중력9.8·원본 배율/회전만 지원한다. 미지원 장치·컴포넌트·스케일·회전·지형/시작점과의 초기 겹침은 전체 거부한다. 상자는 정적 베이크에 섞지 않고 프레임 엔티티로 생성한다.
- 출시용 Photon/Steam 티켓 경계와 자동 씬 로딩 Disabled 전용 SimulationConfig를 유지했다. 개발 앱/익명 폴백을 출시 버튼에 추가하지 않았다.

## 자동 검사와 새 입력 재생

- 단계별 첫 밟기 검사 후 운반·상자를 연결했다. 머리 진입/옆·위 비대상, 기본/유지 튕김 배율·X 밀림, 동시 밟기·반복 차단, 30틱 Shrink/복원, 플레이어 우선·중복/순환 방지, 탈출 제한 전후·속도/관계 정리, 상자 들기/놓기/던지기6/6, 벽 앞 후보 거부·머리 위 선택, 놓을 공간 없음/관계 유지를 검사한다.
- 실제 제품 입력 시나리오에서 밟기·플레이어 운반·상자 운반·두 종류 던지기·놓기·상자 접지를 모두 관찰한다. 매 확정 프레임마다 양방향 관계와 운반 위치를 단언한다.
- 새 러너의 동일 확정120~1440(120간격) 체크섬12개가 일치했다. 최종1440=`557531512491062087`. 전체 값/기록/궤적은 Git 제외 `Logs/QuantumInteractionChecks.txt`, `QuantumInteractionReplay.json`, `QuantumInteractionTrace.txt`다.
- 기존 이동8개·정적6개·로프8개 재생과 상태 전이 단언을 유지했다. 새 코드 실행의 정적720=`3477954269544302552`, 로프960=`16597026499307259588`다. 로프 시나리오 구간 보강 후 결과는 최종 로그를 따른다.
- Main 실제 버튼 → 새 맵 → 자동 입력 플레이 → 위 입력 전원 도착 → Main → 새 맵 재진입/메뉴 종료를 실행했다. 실패/재시도·출시 설정 실패·취소·중복 시작·외부 씬 왕복 뒤 러너0·입력/메뉴 콜백·표시 잔존 없음·Mirror 비활성을 확인했다. 이 오프라인 실행 중 Unity Error/Exception/Assert 0건. `Logs/QuantumProductOffline.txt`.

## 실패 분석

- 첫 자동 시나리오는 점프 유지 입력을60틱에 시작했으나 플레이어가70틱 부근 생성돼 공중에서 누름이 소비됐다. 접지 후120틱 시작으로 옮겼다. 밟기 단언을 없애거나 점프 규칙을 바꾸지 않았다.
- 상자 접근 자동 감속이 시선을 뒤집어 두 번째 들기를 못 했다. 처음에는1.05 거리에서 약한 전진 입력으로 시선을 유지했으나 온라인 지연에서 실제0.2 탐색 범위 밖에 멈췄다. 최종0.85~0.98 거리에서만 시선을 고정해 탐색 범위에 진입시켰다. 게임 수치·던지기 횟수 단언은 바꾸지 않았다.
- 실패 UI 검사에 팔레트 미등록 ID를 넣어 기존 팔레트가 오류를 기록했다. 등록된 미지원 `obstacle.cannon`으로 바꿔 위치/원인 실패 UI와 전체 시작 거부를 검증했다.
- 첫 Photon 회귀는 벽 로프 상승 종료가 천장 직전이라 한 플레이어 천장 접촉이 없었고 벽 낙하 관찰도 없었다. 상승300~390/하강390~460, 지상 벽 점프540~570으로 시나리오 구간을 보강했다. 기존 전이 단언·비관통 범위는 유지하며 실제 확정 입력도 추적한다.

## 한계와 후속

- 다른 PC·Steam 다계정·출시 Steam 공급자/소유권/익명 거부·실제 두 사람 조작·게임패드·플레이어 빌드 실조작·지연/손실 주입은 미실행이다. 개발 Photon의 같은 PC 두 연결을 이 항목들의 통과로 취급하지 않는다.

- 다음 실제 교체는 리셋/추락·운반/상자 관계 초기화 → 장치/기본 스테이지의 지원·명시적 거부 → 친구 맵 전송 → Steam 로비/초대다.
