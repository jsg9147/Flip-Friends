# 제품14 대포/투사체 원본 근거와 검증

- 상태: Historical. 구현 범위와 다음 작업은 [Quantum 전환 문서](../QUANTUM_MIGRATION.md)를 따른다.

## 원본 근거 (Mirror 실제 활성 경로)

- 배치: Stage 4·5·6·8·9·10·11·15·17·18·20·21에 대포 69개(Stage4 11개, Stage20 22개). 모두 `CannonBall.prefab`을 쓰고 이동 발판·OnOff·회전 장치의 자식인 대포는 없다. `PowerCannonBall`은 `CannonProjectile`이 없고 태그가 Reset이라 `TryValidateConfiguration`을 통과하지 못하며 어떤 대포도 참조하지 않는다(미사용, 이식 안 함). `MapEditorCannon`은 `Cannon` Variant+NetworkIdentity다.
- `Cannon.prefab`: Enemy 레이어·Trap 태그, 트리거 Box (1,0.81)/오프셋(0,-0.095) — 몸체 자체가 피격 판정이다. `CannonShooter` 기본 지연0·간격2·탄속10·거리20·방향(1,0).
- 인스턴스 값: 지연 0~2.6(Stage20만 0.2 배수), 간격 2/2.5/3/15, 탄속 5/8/10/11/15/20/30, 거리 5/15/20/25, 방향 (±1,0)/(0,-1). 방향은 Transform 회전·배율과 무관한 월드 값이다(배율-1인데 방향(1,0)인 인스턴스도 있다).
- 발사: `OnStartServer`에서 `next = now + 지연`, `Update`에서 `now >= next`면 포구(정규화 방향×1)에 생성하고 `next += 간격`(밀렸으면 `now + 간격`). 실시간 초 기준이며 50Hz 물리와 무관하다.
- 탄: Kinematic Rigidbody2D(중력 무시)·트리거 원 반지름0.25·Enemy 레이어·Trap 태그. 충돌 처리 코드가 없어 지형·플레이어·상자·다른 탄을 모두 통과한다. 발사점에서 거리 > 최대 거리를 0.1초 간격(생성 시점부터)으로 검사해 제거한다. 풀링 없이 서버 Instantiate/Spawn·씬 종료 때 파괴된다.
- 피격: `PlayerController2D.HandleDamage`가 Trap 태그를 받고 `BasicTrap`이 없어 `(플레이어−탄).normalized` 방향, 제품9 넉백(20,20)·무적·조작 제한·로프 차단·내려놓기와 같다. 들린 플레이어 제외, 상자 피격 없음.
- 레이어: Player 마스크 108992에는 Enemy(10)가 없어 플레이어에겐 비고체. Box 마스크 3392/3520에는 Enemy가 있어 상자는 대포 몸체·탄에 레이로 막힌다.
- 리셋·복귀: 플레이어 복귀·구간 Reset은 탄과 무관하다. 대포 리셋 경로는 없다.

## Quantum 규칙과 원본 차이

- 사용자 결정(2026-11-09): 소멸 규칙은 원본 그대로(통과·거리 초과만), 대포 몸체와 탄은 상자 비대상(원본 Box 마스크 부작용 제외).
- 지연·간격은 `초×60` FP 틱으로 두고 k번째 발사는 `시작 + 지연 + k×간격` 이상인 첫 틱이다. k×간격을 매번 계산하므로 누적 오차가 없고 발사당 오차는 1틱(1/60초) 미만이다. 원본 값(0.2 배수·2/2.5/3/15초)은 모두 정수 틱이라 오차0이고, 시험 맵의 7.5틱 간격은 ceil(7.5k)로 70~79발 모두 일치했다. 원본의 밀린 예약 보정은 틱이 건너뛰지 않아 필요 없다. 간격은 1틱 이상만 받아 틱당 최대 한 발이다.
- 탄속은 초당 값 그대로 `위치 += 속도×DeltaTime`(틱당 변위 = 초당/60). 50Hz 물리와 같은 초당 이동량이다.
- 수명: 6틱(0.1초) 간격 검사. 틱 안 순서는 ①이전 틱 위치로 거리 검사·제거 ②이동 ③대포 ID 순 발사. 원본처럼 제거 직전 위치는 이미 피격 판정을 거친다. 탄속10·거리20은 127틱(원본 약2.1초), 탄속30·거리5는 13틱. FP `10×(1/60)`이 1/6보다 약간 작아 120틱 위치가 19.995라 126틱 검사에서 제거된다.
- 피격: 정적·이동 트랩(ID 순) 뒤에 탄을 본다. 여러 탄이면 (발사 틱, 대포 ID) 가장 이른 탄 하나. 생성 틱의 탄은 판정하지 않는다(원본도 첫 물리 이동 뒤 트리거). 판정은 몸체 AABB와 원(기존 이동 원형 트랩과 같은 식). 탄은 맞혀도 남는다.
- 대포 몸체는 같은 오브젝트의 `QuantumStageTrap`(트리거 Box)로 작성하며 필수다. 이동 대포·다른 장치 혼합은 원본에 없어 거부한다.
- 동시 탄 상한 128. 변환기가 대포별 최대 동시 탄 수(수명/간격+여유)의 합이 넘는 콘텐츠를 거부하고, 실행 중 초과는 발사를 건너뛰되 예약은 진행하고 `DroppedShots`에 남긴다.
- 터널링: 틱당 변위 ≤ 탄 지름(탄속 ≤ 반지름×120)만 받는다. 원본 최대 30/초·반지름0.25가 정확히 경계다.
- 시작은 두 플레이어 등록 틱(이동 장치와 같은 시작 프레임). 전원 도착 뒤 이동·발사·제거를 멈추고 남은 탄은 러너 종료와 함께 사라진다.
- 표시: `QuantumCannonViews`가 예측 프레임의 탄을 풀링한 SpriteRenderer로 그린다. 대포 좌우 방향은 작성 SpriteRenderer.flipX(해시 제외)로 보인다.
