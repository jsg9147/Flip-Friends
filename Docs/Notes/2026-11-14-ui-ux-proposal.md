# Flip Friends UI/UX 개편 기획안

**상태** · 검토용 초안
**범위** · 타이틀에서 플레이 시작까지, 인게임 HUD, 설정, 맵 에디터의 표시 원칙

## 1. 기획 결정

기존 도트 레터링을 타이틀과 주요 화면 제목에 남긴다. 플레이 중에는 아이콘과 숫자를 먼저 쓰고, 로비와 설정에서는 짧은 텍스트로 행동과 상태를 알려준다. 도트 프레임, 선택 테두리, 버튼 간격을 공통으로 써서 표시 방식이 달라도 한 게임처럼 보이게 한다.

- **도트 이미지**는 타이틀 로고, 기존 메뉴 레터링, `STAGE` 제목, 조작 아이콘에 쓴다. 이미 있는 아트를 우선 사용한다.
- **아이콘과 짧은 라벨**은 `친구 초대`, `코드로 참가`, `준비`처럼 처음 보는 플레이어가 구분해야 하는 행동에 쓴다. 색과 아이콘으로 빠르게 훑고, 라벨로 의미를 확인할 수 있게 한다.
- **텍스트**는 방 코드, 이름, 키 바인딩, 실패 이유처럼 값이 바뀌거나 정확히 전달해야 하는 정보에 쓴다. 긴 이름은 목록에서 한 줄로 줄이고 선택 상세에서 전체를 보여준다. 방 코드는 전체를 표시하고 복사할 수 있게 한다.

한국어 문구는 흐름을 설명하기 위한 예시다. 출시 언어는 대상 플레이어가 정해질 때 결정한다. 새 고정 라벨은 화면 로직과 분리해 나중에 교체할 수 있도록 한다. 기존 영어 레터링을 번역할 필요가 생기면 해당 자산도 교체 대상에 포함한다.

## 2. 타이틀에서 플레이까지

타이틀은 기존 `Start → Settings → Map Editor → Exit` 구성과 아트를 유지한다. `Start`를 누르면 플레이 방식부터 고른다.

- **같은 PC에서 플레이** → 인원과 입력 장치 확인 → 맵 선택 → 시작. 장치가 부족하면 시작 버튼 가까이에서 이유를 보여준다. 예시는 `3명이 플레이하려면 패드 1개를 더 연결하세요.`
- **온라인 플레이** → `방 만들기` 또는 `코드로 참가` → 같은 로비 화면. Steam 초대로 들어온 플레이어는 해당 방으로 이어진다. 코드 참가에는 붙여넣기 가능한 입력란을 둔다.

맵 선택에는 `공식`과 `커스텀` 두 탭을 사용한다. 공식은 번호와 썸네일, 커스텀은 이름을 기준으로 찾는다. 확정한 맵은 화면을 돌아와도 식별할 수 있게 표시한다. 현재 준비 화면에 섞인 기능 검증용 맵은 개발용 진입점에서 접근하도록 제안한다.

## 3. 우선 개편 화면 · 온라인 로비

- **상단**에 방 코드와 `코드 복사`, `친구 초대`를 둔다. 복사가 끝나면 버튼 근처에 `복사됨`을 잠깐 표시한다. 초대는 현재 초대 권한이 있는 플레이어에게 표시한다.
- **가운데**에 최대 4개의 플레이어 슬롯과 확정 맵을 보여준다. 플레이어 행에는 이름, 방장 표시, `준비` 또는 `준비 전`을 표시한다. 맵 선택은 방장에게 제공하고 참가자에게는 같은 맵의 이름과 썸네일을 보여준다.
- **하단**에 내 준비 상태를 바꾸는 `준비` 또는 `준비 해제`와 `나가기`를 둔다. 방장에게는 `시작`도 표시한다. 시작을 막는 조건이 있을 때는 버튼 가까이에서 현재 이유 한 가지를 보여준다. 예시는 `맵을 선택하세요`, `1명이 아직 준비하지 않았어요`.
- **맵 공유 중**에는 `맵 받는 중…`을 표시한다. 공유에 실패하면 현재 로직에서 가능한 행동을 안내한다. 예를 들어 방장은 다른 맵을 선택할 수 있다.
- **참가에 실패했을 때**는 원인을 알 수 있는 범위에서 알려준다. `방이 닫혔어요` 또는 `방 코드를 확인해 주세요`를 해당 상태에 맞춰 표시하고, 코드 입력 화면에서는 입력값을 유지한다.
- **플레이에서 돌아왔을 때**는 기존 방이 있으면 로비와 새 준비 상태를 보여준다. 방이 닫혔으면 온라인 진입 화면에 이유를 표시하고 다시 참가할 수 있게 한다.

현재 준비 화면의 `Steam Quantum 로비 만들기`는 `방 만들기`로 줄인다. 현재 한 버튼에서 바뀌는 초대·초대 수락·코드 참가 문구는 온라인 진입과 로비 안의 행동으로 나눈다. 화면마다 플레이어가 다음에 누를 버튼 하나를 강조한다.

## 4. 다른 화면의 적용 기준

- **플레이 HUD** · 체크포인트, 구간, 소환 대기는 아이콘과 숫자로 표시한다. 처음 배우는 들기·던지기는 실제 입력 아이콘과 동작 이름을 함께 보여준다. 이후 플레이 중에는 입력 아이콘이 필요한 순간에만 나타난다.
- **설정** · 기존 도트 제목과 키 설정 프레임을 유지한다. 키 설정은 동작 이름과 현재 입력값을 같은 행에 둔다. 음량은 아이콘과 수치로, 풀스크린·창 모드는 읽을 수 있는 라벨로 표시한다.
- **맵 에디터** · 배치·삭제 등 자주 반복하는 도구에 아이콘을 쓰고, 포커스나 호버 시 도구 이름을 보여준다. 저장·불러오기·검증 실패에는 행동과 결과를 텍스트로 표시한다.
- **입력 피드백** · 스테이지 선택의 기존 표현을 공통으로 사용한다. 연두색 표시와 체크 등으로 확정 상태를, 주황색 외곽선으로 현재 호버 또는 입력 포커스를 표시한다. 패드·키보드에서도 맵 선택을 마친 뒤 로비의 유효한 버튼으로 돌아갈 수 있게 한다.

## 5. 작업 순서와 확인 방법

1. **로비 한 흐름부터 만든다.** 기존 도트 프레임을 사용해 온라인 진입 → 방 만들기·참가 → 준비 → 시작 화면을 정리한다. 정상 흐름에 더해 잘못된 코드, 미준비 인원, 커스텀 맵 수신과 실패, 플레이 뒤 로비 복귀를 먼저 확인한다.
2. **처음 보는 사람에게 방장과 참가자 역할을 맡긴다.** “친구와 같은 방에 들어가 게임을 시작해 주세요”라고만 안내한다. 도움 없이 완료했는지, 잘못 누른 첫 버튼이 무엇인지, 시작이 막혔을 때 이유를 말하고 다음 행동을 찾는지 기록한다. 초대와 코드 참가를 각각 확인하고, 키보드·패드로 돌아오기와 포커스 복귀도 검사한다.
3. **통과한 표현을 다른 화면에 적용한다.** 로비에서 반복해서 헷갈린 라벨과 상태를 먼저 수정한다. 그 뒤 같은 PC 준비 화면과 맵 선택에 공통 프레임을 적용하고, HUD·설정·맵 에디터 순으로 필요한 부분을 손본다.

첫 개편의 완료 기준은 새 플레이어가 설명 없이 방에 들어가 준비할 수 있고, 방장이 시작 조건과 막힌 이유를 화면에서 확인할 수 있는 것이다. 1600×900과 지원하는 작은 창 크기에서 긴 맵·플레이어 이름, 전체 방 코드, 선택 테두리가 잘리지 않는지도 확인한다.
