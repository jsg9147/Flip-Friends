# 기본 스테이지 장치와 참조 검증

- 상태: Active
- 범위: 기본 Stage 1~21, 스위치·전환 지형·벨트와 에디터 참조 검사.

## 현재 상태

- 단계 0~5의 코드·참조 정리와 격리 검사를 완료했다. 로컬 KCP 실제 소켓·물리·씬 회귀를 추가했으며 실조작 전체 클리어와 Steam 검증은 남아 있다.
- 대포는 서버에서 속도·발사 위치·최대 거리를 초기화한 뒤 Spawn한다. `CannonProjectile`이 대포와 독립적으로 거리 초과를 검사하고, 원격 클라이언트는 Rigidbody2D 시뮬레이션을 끄고 서버 위치를 따른다. 대포 중지/비활성화 시 발사 예약을 해제한다.
- CannonBall 프리팹에 수명 컴포넌트를 추가하고 NetworkTransform을 ServerToClient로 복구했다. 회전 장애물의 랜덤 속도·방향은 서버에서 한 번 결정해 전송하며 기존 회전/NetworkTransform 방식을 유지한다.
- DynamicObj는 초기 위치 기준으로 인원 오프셋을 적용해 반복 호출 시 누적되지 않는다. Stage 1~6의 NetworkTransform 대상 6개를 자기 Transform으로 명시했다. 클리어는 서버가 직접 기존 ReturnRoomScene을 한 번 호출하며, 기존 Command도 완료 상태를 다시 검사한다.
- 발판은 `PlatformMotion`에서 시작 시각·경로·속도·대기를 평가한다. 기존 진행률/초와 마지막 진행률의 float 누적 틱을 보존한다. 틱마다 위치를 RPC로 보내거나 플레이어를 발판에서 직접 이동시키지 않는다.
- 감지 발판은 서버가 감지 대기/출발 지연/이동/완료를 관리한다. 리셋은 최초 위치·시계·진행 상태·감지 지연·판정·알파를 복원하고 세대를 바꾼다. 복귀 코루틴과 페이드 Tween을 제거해 이전 예약이 재실행되지 않는다.
- 플레이어 입력의 발판 시각과 상태의 탑승 부품·세대·시각을 전송한다. 서버/예측/재시뮬레이션이 같은 식의 이동량을 `Simulate` 안에서 적용하고 판정 시점의 발판 위치·충돌을 임시 적용 후 복원한다. 점프와 리셋 세대 변경 시 이전 운반을 중단한다.
- Stage 15·16·17의 로컬 렌더러 4개와 Stage 21 벨트 Player 감지 마스크를 복구했다. Stage 12 레이저 막대 2개·20 이동 함정 3개는 트리거 장애물로 탑승 기능을 명시적으로 끄고 마스크 0을 유지한다. Stage 20·21 벨트의 렌더러 null은 낙하/소멸 연출이 꺼져 있어 허용한다.
- 기본 발판은 Player 마스크를 유지한다. 느슨한 상자의 별도 탑승 운반은 추가하지 않았으며 들고 있는 상자는 플레이어를 따른다. Stage 20 벨트의 기존 speed=0도 유지한다. 팔레트에는 PlatformController가 없다.
- Reset 접촉은 서버 `RespawnHandler`만 처리하며 같은 물리 스텝의 동일 대상 중복 호출을 막는다. 플레이어의 별도 Reset Command 접촉과 상자의 별도 접촉 처리를 제거했다.
- 플레이어 구간 복귀는 `ServerResetSection` → `ServerMover.Teleport`로 운반 상태를 유지한다. `onlyBoxReset`은 기존처럼 상자를 든 플레이어만 이동시킨다. 리셋 키·추락은 들고 있던 대상을 내려놓고 체크포인트/최초 생성 위치로 복귀한다.
- 상자 `ServerReset`과 `Release`는 위치·속도·충돌 상태·동기화 위치·운반 상태를 함께 갱신한다. 재소환 시 운반자의 참조·표시·충돌 무시도 해제한다. 운반 상태는 SyncVar hook으로 표시한다.
- `ObjSummonSwitch`는 상자 API만 호출하고 쿨다운 상태·종료 시각을 동기화한다. 체크포인트 선택은 서버만 수행하고 더 큰 ID만 수용한다. 기존 중복 ID는 최초 도달 지점을 유지한다.
- 기본 스테이지 자식 상자의 운반 참조는 NetworkBehaviour(루트 netId + 부품 인덱스)로 전송한다. 자식 NetworkIdentity를 추가하지 않는다.
- Stage 8 Grid/ResetTile은 사용자 확인으로 불필요한 배치임을 확정해 오브젝트를 제거했다. 세 상자와 각 소환 위치는 유지했다. [조사 근거](Notes/2026-10-26-stage-respawn.md).
- `Switch`는 서버의 `SetSwitchState`로 상태를 변경하고 SyncVar hook으로 표시를 갱신한다. 서버 효과 콜백은 hook에서 다시 호출하지 않는다.
- `LayerBasedSwitch`는 서버에서 유효 콜라이더 집합을 관리해 마지막 접촉이 해제될 때 비활성화한다. 중복 진입·비활성/파괴 콜라이더를 정리한다.
- `OnOffSwitch`는 자신의 이전 bool 대신 매니저의 현재 상태 반전을 요청한다. 매니저는 소속 스위치 내부 상태·지형·벨트를 함께 적용한다.
- 그룹 상태와 벨트 방향은 각각 SyncVar로 전달되며 초기 클라이언트 생성에서도 적용된다. 벨트는 초기화 시 매니저가 설정한 방향을 덮어쓰지 않는다.
- 스위치→매니저 및 매니저→스위치 참조 60개가 일치한다. 빠졌던 역방향 스위치 목록 46개를 복원했다.
- 모든 Conveyor 27개가 매니저 하나에 연결된다. 미등록 벨트 16개를 연결했다.
- Stage 20 고정 벨트 9개는 Auto OnOffManager, 이동 벨트 (9)는 일반 OnOffManager가 제어한다. Stage 21 이동 벨트 (6)는 자식 스위치와 같은 일반 매니저가 제어한다.
- 사용자 결정에 따라 Stage 20·21의 두 매니저 모두 기존 자동 토글 활성화·간격을 유지한다.
- Stage 12·13·14·16·17의 전환 지형 참조 10개와 Stage 21의 null 벨트 목록 4개를 정리했다. 비어 있거나 존재하지 않는 전환 지형은 선택 값으로 허용한다.
- Stage 15·16 각 1개와 17의 2개 리셋 버튼에 같은 부모의 유일한 발판·현재 스프라이트의 눌림 쌍·Player 마스크를 연결했다. 기존 일반 콜라이더와 판정 크기는 유지하며 아래에서 머리로 누르는 감지를 지원한다. Stage 21의 정상 참조는 보존했다.
- Stage 15~19 상위 문 그룹의 외부 참조 없는 DoorSwitch 10개만 제거했다. 그룹 오브젝트·콜라이더·자식 문 스위치를 보존했다. 실제 문마다 스위치가 하나인 사용례를 확인했으며 다중 제어 규칙은 도입하지 않았다.
- 문 표시는 초기/변경 SyncVar 적용에서 캐시된 렌더러·콜라이더를 함께 갱신한다. 리셋 버튼은 눌림 진입에서 서버 발판 API를 한 번 호출하고 해제 시 재호출하지 않는다. 서버의 발판 판정·연출 복원도 RPC 없이 적용된다.

## 핵심 흐름

- 입력: `OnOffSwitch.ToggleSwitch` → `OnOffManager.ToggleState` → 서버 그룹 상태 변경.
- 적용: 소속 스위치 `SetSwitchState` → 전환 지형 활성화 → `Conveyor.UpdateConveyorState`.
- 표시: 각 SyncVar hook 및 `OnStartClient`가 서버 상태를 반영한다. 표시에서 서버 효과를 재호출하지 않는다.
- 에디터: `Assets/01_Scripts/PlayingScripts/Editor`의 검사·복구 메뉴를 사용한다.
