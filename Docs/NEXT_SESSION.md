- 기존21개 스테이지·일반 장치·MapEditor 테스트·친구 맵 전송·Steam 로비/초대는 Mirror다. 현재 제품은2인 전제이며 목표4인 확장이 남아 있다.
- 기존21개 스테이지는 사용자가 새로 구성해 프리팹 기반 공식 맵으로 등록할 예정이다. 원본 프리팹은 보존한다.
- 최신 검증과 미실행 환경은 [공통 검증](QUANTUM_MIGRATION.md#검증)을 따른다. 문서 정리로 새 실행 통과를 주장하지 않는다.
- 실제 프로젝트 버전은 ProjectSettings/ProjectVersion.txt의6000.6.8f1, SDK는 Quantum3.0.14 Stable2241이다. 임의 업그레이드하지 않는다.

## 확정 방향 (2026-11-08 사용자 결정)

- 21개 스테이지는 사용자가 새로 구성해 **공식 맵**으로 등록한다. 경사·움직이는 지형을 포함해 모든 기능을 쓴다.
- 공식 맵은 **Unity 프리팹(Tilemap)으로 만들고 Quantum 데이터로 변환**한다. MapEditor는 유저 맵·친구 맵 용도로 유지하고, MapData 규칙(x−50~50 등)은 그대로 둔다.
- 공식 맵 프리팹에는 Mirror 스크립트 대신 **Quantum 작성 전용 컴포넌트**를 쓴다. 두 경로는 같은 FP 지형·장치 데이터와 시뮬레이션 규칙을 공유한다.
- 원본 Stage7 등 기존 스테이지 그대로의 이식은 보류한다([Stage7 검사 기록](Notes/2026-11-08-quantum-stage7-tilemap.md)).

## 다음 작업 — 공식 스테이지 변환 경로

1. 작성 전용 컴포넌트를 정의한다: 시작점, 도착, 상자, Reset(목적지·마스크·onlyBox), 체크포인트, 소환. 지형은 기존과 같이 Ground Tilemap+Composite에서 읽는다.
2. `QuantumTilemapSetup`의 Stage1/Stage9 전용 생성을 범용 작성기로 바꾼다. 공식 스테이지 프리팹 하나를 지정하면 검증, 베이크, manifest 생성이 된다. 기존 거부 규칙(경사8raw·상한·교차·열린 윤곽·비유한 값·다중 Collider 장치)은 유지한다.
3. 시작점·도착·상자는 MapData 오브젝트가 아니라 작성 컴포넌트에서 읽는다. MapData 배치 범위는 공식 경로에만 적용하지 않는다(MapEditor 쪽 규칙은 그대로).
4. 공식 맵 목록 자산을 두고 Main 준비 화면에서 고른다. 개별 `Resources.Load`·버튼 하드코딩을 목록 기반으로 바꾼다.
5. 기존 2:2~6:6의 원본·베이크·해시를 보존하고 재검증한다. 작은 시험 공식 프리팹 하나로 새 입력 기록·결정론 재생·기존 제품 경로 회귀·같은 PC 개발 Photon 두 연결을 실행한다.
- 이 묶음에서는 경사 이동·움직이는 지형·새 장치를 구현하지 않는다. 확정 정책은 [장치 기록](Notes/2026-11-08-quantum-devices.md)을 유지한다.

## 전체 교체 순서

1. 공식 스테이지 변환 경로(위 묶음)와 공식 맵 목록·선택.
2. 경사 이동(원본 Controller2D 기준, 체감 수치는 확인받음)과 작성기의 경사 수용.
3. 피격/넉백 → 스프링/바운스 → 이동·전환 지형/발판 → 스위치/문 → 컨베이어·장애물/대포/투사체. 각 장치는 작성 전용 컴포넌트에서 변환한다.
4. 사용자가 새로 구성한 공식 스테이지를 등록하고 인원·선택/완료/복귀를 연결한다. 원본 프리팹은 보존한다.
5. 최대4인 전제, 키 재설정/게임패드·장치 배정, 애니메이션/효과음/카메라 연결.
6. MapEditor 검증/베이크·Quantum 테스트 플레이·커스텀 맵 선택/친구 전송/실패 복구.
7. Steam 로비/초대→Quantum 세션, 준비/취소/이탈/재시도·진행 중 입장 제한.
8. 제품 경로 교체와 검증 후 Mirror 전용 참조/진입점·패키지 정리 여부 결정.
- 신규9개 스테이지 제작은 전환 필수 작업과 분리한다. 출시 앱 준비는 위 구현과 병행할 수 있다.

## 동작 문제 수정 기준

- 관통/겹침·발판 승객 이동·동일틱 상태 경합·운반 참조·입력/타이머 잔존·장치 다중 접촉·콘텐츠 참조·자원 누수를 각 이식 묶음에서 조사·수정한다.
- 현재 결함/전환 위험/의도된 동작/수정 완료 회귀를 구분하고 확정 상태·실제 입력·실제 설정값으로 판단한다.
- 플레이어별 체크포인트 단조 증가, 구간 운반 유지/원자적 대기, 막힌 소환의 상태/쿨다운 불변, onlyBoxReset 의미를 유지한다. 비활성 벽 점프나 일반 점프 차단을 새로 켜지 않는다.
- 규칙/체감 변경의 중대한 미확정만 사용자에게 질문한다. 확실한 결함 수정·회귀 검사는 독립적으로 진행한다.

## 외부 조건과 보존

- Steam 출시 앱 미발급. 출시 Photon/Steam 공급자·소유권/익명 차단과 실계정 검증은 [보안 Draft](QUANTUM_SECURITY.md)를 따른다. 개발 익명 폴백을 출시 경로에 넣지 않는다.
- 다른 PC·실제2~4인·배포 빌드·Steam 다계정·지연/손실 주입은 실행 여부를 따로 기록한다. 기존 Mirror 실조작 미완료 항목은 해당 기능 문서에 남긴다.
- 기존 미커밋 변경·미저장 씬과 원본 맵/프리팹을 보존한다. 제품 자동 씬 로딩 Disabled를 유지한다.
