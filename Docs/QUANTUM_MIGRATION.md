- 제품5/ff-product-5에 Reset(1P R·2P Backspace)·플레이어/상자 추락 복귀를 연결했다. 운반 관계/운동 상태를 원자적으로 정리하고 목적지 점유 시 충돌 없는 복귀 대기로 처리한다. Main 네 번째 복귀 맵은4:4, 기존2:2/3:3 맵은 원본/해시를 보존하며 제품5에서 경계/초기 위치를 재검증한다. [복귀 구현·검증](Notes/2026-11-08-quantum-respawn.md)을 따른다.

- Main Start → 준비 화면의 정적/로프/밟기·운반·상자/복귀/장치/Tilemap 사용례 6종 또는 공식 스테이지 선택 → 오프라인 2인 → QuantumPlay → 위 입력 전원 도착/메뉴 종료 → Main·재진입이 제품 경로다. 시험 Bootstrap이나 Mirror 플레이어가 전제 조건이 아니다. 전체 게임 전환은 미완료다.
- 제품 세션/입력/콘텐츠/씬 수명/표시 책임을 분리한다. 밟기·운반·던지기·놓기·상자 충돌/중력은 Quantum FP/DeltaTime과 프레임 상태로만 처리하며 Unity는 입력 수집·표시를 맡는다. Mirror 이동·물리·Animator는 생성하지 않는다.
- 60Hz 이동의 걷기4·달리기5.5·SmoothDamp0.4/반전0.7·공중 제어·가변 점프·조건부 달리기 점프 보너스·로프18틱과 충돌 순서를 보존했다. 벽 미끄럼/벽 점프의 기존 활성 대입 경로가 없어 켜지 않았다.
- 밟기는 이전 이동의 머리 접촉을 소비해13.2(점프 유지×1.2)로 튕기고 X 위치 차×0.5를 더한다. 반복 밟기/등반 차단18틱·밟힌 쪽9틱, Shrink30틱과 (0.8,0.5)/(0,-0.25) 판정을 프레임에 둔다. 기존 BlockJump는 일반 점프 입력을 막지 않으므로 새로 활성화하지 않았다. 기본 판정은 기존 Quantum (0.8,1)/오프셋0을 유지한다(Mirror 기본 (0.9,0.8)/(0,-0.1)과 차이). 머리 위에 서는 상태는 추가하지 않았다.
- 플레이어 우선 탐색·0.2 레이10개·너비/8 간격·머리 위 점유 검사·양방향 운반 관계를 구현했다. 같은 틱은 전역 PlayerRef 순서이며 자기/중복/연쇄/순환 운반을 막는다. 운반 위치(0,0.95)·해제9틱·탈출90틱/요청15틱·플레이어 던지기(7,12)/제한24틱·상자 던지기(6,6)·중력9.8/수평 감속1.5초/낙하12다. 던진 플레이어의 제한은 기존처럼 수평 스무딩1초이며 입력 전체 무시는 아니다.
- 놓기는 앞→머리 위→운반자 자리 순서로 검사한다. 마지막 후보도 검사해 모두 막히면 운반을 유지한다(기존 무검사 fallback과 의도적인 차이). 도착 시 안전하게 내려놓고 관계/속도/타이머를 정리하며 놓을 공간이 없으면 완료를 보류한다. 종료는 러너·연결·입력/메뉴 구독·표시를 정리한다.
- 고정 키: 1P A/D·W/S·Space·왼쪽 Shift·E, 2P 방향키·오른쪽 Ctrl·오른쪽 Shift·Enter. 아래+들기는 놓기다. 온라인 키보드는 각 연결의 로컬슬롯0이며 자동 검사만 GetLocalPlayers로 전역 PlayerRef를 얻는다. Reset은1P R·2P Backspace이며 기존 키 재설정/게임패드는 미연결이다.
- MapData2.1 유지. 기존 정적/로프2:2·상호작용3:3·복귀4:4·장치5:5의 원본/베이크/해시를 보존하고 Tilemap은6:6이다. 공식 스테이지는 `공식1:<해시>`다. 현재 규칙은 `제품8`·온라인 `ff-product-8`이며 경사 규칙도 합의 서명에 포함한다. 상자는 원본 interactive.box 루트0.9·중력9.8·배율1/회전0만 지원하며 미지원 장치/구성은 위치·원인과 함께 전체 거부한다.
- 새 지원 맵은 별도 원본/베이크/manifest/작성 씬으로 Unity API 저장·재로드했다. Main은 런타임 등록을 사용하며 기존 미저장 씬·미커밋 변경·원본 맵을 보존했다.
- 제품 전용 FlipFriendsProductSimulationConfig의 자동 씬 로딩 Disabled를 유지하며 QuantumGameFlow가 씬 수명을 소유한다. SDK 기본 설정으로 되돌리지 않았다.
- 실제 Unity6000.6.8f1·Quantum3.0.14 Stable2241·Steamworks.NET2024.8.0이다. 버전은 변경하지 않았다. [공식 지원 표](https://doc.photonengine.com/quantum/v3/getting-started/initial-setup)의6000.6 미명시와 프로젝트 실행 성공은 별개다.
- 기존 Steam 게임 버튼·Steam 로비/초대·MapEditor 테스트·친구 맵 전송·21개 스테이지는 Mirror다. 일반 장치/스프링/바운스/피격은 미이식이다. 출시 온라인은 별도 출시 Photon 앱/실제 Steam 티켓이 필수이며 미설정 실패 UI·익명 폴백 없음이다. 개발 익명 연결은 UNITY_EDITOR에만 있다. 출시 앱 미발급·공급자/소유권 검증 미완료로 보안 문서는 Draft다.
## 핵심 흐름

- Main Start → `QuantumPrepareScreen` → `QuantumGameFlow` → `QuantumGameSession` → 입력 → 이동/완료 시스템 → 확정 프레임 → `QuantumGameView` → Main.
- 온라인: `SteamPhotonTicket` → Photon Steam 인증 → 2명 대기 → 방 닫기 → Quantum 시작. 초기 시험은 최대 2명이며 제품 목표 4명 검증은 남아 있다.
- `QuantumTestSceneSetup`은 SDK 씬 생성·맵 베이크 API로 정적 지형을 만들고 저장·재로드한다. 기존 테스트 씬을 덮어쓰지 않는다.
- `QuantumReplayCheck`는 기록 입력을 새 러너에서 재생해 같은 확정 프레임의 체크섬과 2명 생성을 대조한다.
- `QuantumCloudCheck`는 특정 개발 앱만 사용하는 에디터 전용 익명 2연결 시험이다. 플레이어 빌드에 포함되지 않으며 출시 구매 인증의 증거가 아니다.

## 남은 작업

- Steam 앱 발급 후 별도 출시 Photon 앱에서 Publisher Web API 키를 직접 등록하고 공급자 `version=2`, `identity=photon`, `verifyOwnership=true`, 익명 거부를 설정·검증한다. [보안 기준](QUANTUM_SECURITY.md)을 따른다.
- 지원 지형 밖의 장치·추가 맵·45도 초과/동적 콜라이더와 친구 맵 전송은 별도 이식 범위다.
- 공식 맵은 Unity 프리팹(Tilemap)+Quantum 작성 전용 컴포넌트로 만들고 변환한다. 21개 스테이지는 사용자가 새로 구성해 등록한다. MapEditor는 유저·친구 맵용이며 MapData 규칙을 유지한다. 장치·경사 지원 뒤에 친구 맵 전송 → Steam 로비/초대 순서로 교체한다. 원본 프리팹은 보존하고 비활성 벽 점프는 새로 켜지 않는다.
- 현재2인 전제를 최대4인으로 확장하고 키 재설정/게임패드·표시/카메라·제품 진입을 연결한다. 기존21개 프리팹 맵의 새 배치와 신규9개 제작은 구분한다.
